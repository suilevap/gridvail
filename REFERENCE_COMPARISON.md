# Comparison with PavEcsLiteGame

Reviewed against [upstream commit bc0b449f68d953861932214b85110f99925d886a](https://github.com/suilevap/PavEcsGame/tree/bc0b449f68d953861932214b85110f99925d886a), on 2026-09-20.
The target is `PavEcsLiteGame`; the legacy demo and Tetris are outside this port.

## Evidence

| Area | Result |
| --- | --- |
| Assets | All five maps and four rule files match upstream byte-for-byte. |
| Field of view | 5,769 samples match the original C# algorithm within `1e-5`: all five maps, open field, northwest angular seam, east wall, and closed ring. |
| Light merging | 2,880 cases match C# exactly across light kinds, initial brightness, distances, radii, and fractional visibility. |
| Palettes | All 1,024 entries match C# exactly (256 intensities × four kinds). |
| Spawn configuration | Reviewed six map entity kinds, player sight/light radii, light values, token recharge, friction, and marker rotation against `SpawnEntitySystem`. |
| Collision contract | Swaps stay blocked, contenders reserve cells before vacating, and collisions are recorded without damage (the Lite container disables that consumer). Existing tests cover swaps/contention; a new regression covers direct wrapped requests and first placement. |
| Live pipeline | Tests cover idle player input with tokenless enemies, timed enemy recharges, one input edge per press, blocked movement, same-frame marker placement, and finite visibility. |
| Rendering | Actual GPU screenshots captured at spawn `(8,5)` and after walking to electricity at `(12,17)`. Unicode symbols, connected wall glyphs, camera margins, HUD, remembered terrain, and light colors were inspected. |

The independent fixtures are generated by `tools/generate_reference.py` from
the pinned C# checkout, **not from the Rust implementation**. The generator
compiles the original FOV/range classes, the exact `Int2` type and helpers,
and the light-merge/context and palette routines extracted from their ECS
wrappers. It omits unrelated `Float3` code with invalid upstream overload
calls. Fixtures preserve raw C# floating-point output, including tiny negative
roundoff; the Rust result clamps to `[0, 1]`.

Run `cargo test` for all 37 tests. Run
`cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` for code checks.
The existing Bevy dependency graph emits a future-compatibility warning for
`block 0.1.6`; macOS debug linking also warns about large unwind information.
These did not prevent tests or GPU execution.

## Fixes from the review

- Bevy's default FOV resource now enables the same circular intervals as the
  explicit constructor; northwest walls no longer leak light/sight across
  the angular seam.
- Visibility output clamps small floating-point excursions.
- Tokenless commands do not keep the simulation phase open. Only executable
  commands count; doomed entities are excluded. The core tokenless-command
  correction was already present when the Git baseline was taken and now
  has a deterministic integration regression.
- Direct movement requests commit the same wrapped destination checked by
  the collision resolver. First placement is covered too.
- The marker follows the player's final, collision-resolved position in the
  same frame, including blocked moves.
- Static lighting responds to brightness/type edits without requiring a
  position or FOV revision change.
- A licensed, embedded DejaVu Sans Mono font replaces the limited default
  font. Console-shaped cells join box-drawing glyphs; camera fitting prevents
  narrow-window map clipping. The HUD wraps within the window.
- Headless tests now advance explicit time and clear input edges, instead
  of accidentally treating `just_pressed` as permanently true.

## Intentional differences and limits

- One Bevy world replaces the C# type-world universe.
- Simulation phase reflects remaining executable work; it does not reproduce
  the original per-system flags' extra settling passes or identical tick counts.
- The marker updates after movement rather than one pass later.
- Wall masks are computed in two phases rather than reproducing the original
  neighbour-mutation bug. FOV invalidates on blocker-layout changes, and static
  lighting replaces the original unreliable XOR version counter.
- The player's invalid/null direction-rule lookup is omitted, retaining `@`.
- Rust and C# use different seeded random streams; enemy trajectories are
  not expected to match. Entity arbitration is deterministic by Bevy entity
  index/generation, not a claim of identical cross-engine filter order.
- WASD is added; native Bevy input uses press edges rather than terminal
  key-repeat events. Input during actual simulation work is still dropped,
  matching the original policy.
- The window uses an explicit font and RGB approximations of console colors.
  Screenshot mode fixes the timestep for reproducible captures; ordinary
  play uses Bevy's clock. Screenshot mode disables pipelined rendering to
  avoid a confirmed macOS shutdown deadlock in `RenderAppChannels::drop`;
  normal rendering is unchanged by that workaround.
- The original console application was not run end-to-end. These are source,
  algorithm, integration, and Bevy rendering checks, not proof of identical
  full-game replays or pixel-identical terminal output.
- All assets ship, but `map1` remains the startup map; runtime map selection,
  combat, and Tetris were not added.

## Screenshot reproduction

```sh
cargo run -- --screenshot screenshots/bevy-map1.png
cargo run -- --screenshot screenshots/bevy-explored.png --walk LLLUUURRRRRRRDDDDDDDDDDDDDDD
```

Both images come from Bevy's actual rendered window. The second uses input
replay rather than teleportation or overriding visibility. A desktop session
with GPU access is required. PNGs are ignored by Git; the capture code and
reproduction commands are committed.
